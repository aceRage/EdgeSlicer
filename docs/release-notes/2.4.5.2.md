# EdgeSlicer 2.4.5.2

<!-- update-notice -->
New in 2.4.5.2:
- Windows builds are now digitally signed, so Smart App Control and antivirus no longer block them
- Upgrades close the background Mobile Hub by themselves (no more Task Manager)
- Clearer messages when the network plug-in can't load
- Vendor connectors: import from a link or pasted text, and update an existing one
<!-- /update-notice -->

Everything in [2.4.5.1](https://github.com/aceRage/EdgeSlicer/releases/tag/v2.4.5.1-edge) is included.

## New

- **Signed Windows builds** (#426). Every executable and DLL we ship, the installer and the uninstaller now carry an Authenticode signature (Microsoft Artifact Signing, timestamped). Windows Smart App Control and antivirus tools that require signed code stopped flagging EdgeSlicer in our test. SmartScreen's "unrecognised app" notice may still show for a while until the new signature builds reputation. The FlashNetwork plug-in DLL and the installer's own NSIS helper DLLs are not ours and stay unsigned.
- **Vendor connectors: import from a link or pasted text** (#427). Home > Vendors > Import now offers From file, From link (https only) and Paste JSON, and each connector's menu has Copy JSON for sharing. Every import shows what it will add and where your credentials would be sent before saving. Credentials are never imported or exported; set them with Credentials > Set. Links of the form `edgeslicer://connector?url=...` open the import with the address filled in.
- **Update an existing connector on import** (#427). Importing a connector with the same name offers Update (keeps your saved credentials) or Add as a new connector. If the update changes the API address, it says so and suggests adding a new one instead.

## Behaviour changes

- **Upgrades and uninstalls close the Mobile Hub** (#425). The installer asks a running hub (also an older version's) to quit, then ends anything still running from the install folder, including the hub's camera helpers. It never touches other EdgeSlicer folders. An open EdgeSlicer window is not killed: you get a Yes / No / Cancel prompt, and Yes closes it normally so you can save. A silent install closes the hub and stops with an error if a window is open.
- **Vendor list buttons** (#427): "Refresh list" is now **Fetch Changes** and "Fetch everything again" is **Full Refresh**. After you change a connector's settings, the next Fetch Changes reads every model again, so new page links and fields apply everywhere.
- **The old "legacy network plug-in" setting is ignored** (#424). A `legacy_networking` setting carried over from an older install made the app reject the current network plug-in, so Bambu sign-in kept saying "please restart". It is now turned off automatically.

## Fixes

- **"The network plug-in is installed but not loaded yet"** no longer repeats forever (#424). When the plug-in can't load, the message now says why: blocked by Windows or antivirus, missing or damaged, a missing Windows component, or a version mismatch, with the error code. The log records the full details. A long Windows user folder path no longer stops the plug-in from loading.
- **Vendor downloads** no longer get a double extension such as `.3mf.3mf` (#427).

## Known limitations and not tested

- Checked by hand: the signed installer under Smart App Control (one Windows 11 machine), the plug-in messages and the legacy setting (#424), and the connector import, update and download flows (#427).
- Not tested end to end: the installer's upgrade path with a running hub from an older version on a second machine (#425), and the new connector flows on macOS.
- SmartScreen reputation for the new signature builds over time; a warning on the first downloads is expected.

## Under the hood

- Signing runs on the Windows build machine with Microsoft Artifact Signing (Azure), signed in through GitHub's OpenID Connect; no signing key is stored anywhere. Releases fail if any shipped file is unsigned. See `docs/windows-signing.md`.
