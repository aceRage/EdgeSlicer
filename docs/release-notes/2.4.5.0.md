# EdgeSlicer 2.4.5.0

<!-- update-notice -->
New in 2.4.5.0:
- New G-code preview: much lighter on graphics memory, new views for actual speed, actual flow, acceleration, jerk and pressure advance, an option to dim lower layers, and a default view type setting. It needs OpenGL 3.2 core, which the app now asks for.
- Costs: a cost breakdown after slicing, your own filament prices and machine rates, and fees plus markup for a selling price.
- Import a PNG or JPG and emboss it as multi-colour shapes, one part per colour.
- Texture displacement (from OrcaSlicer) for surface textures.
- A Printers tab that monitors all your printers, and Printer Selection as one sortable, filterable table.
- Text, SVG and image tools: easier to grab, plus 3D move and rotate handles.
- Snapmaker U1: Snapmaker filaments, a 0.4+0.6 mixed-nozzle machine, and new installs start on the 0.4 nozzle.
- Dozens of OrcaSlicer fixes ported (crash guards, support, infill, walls, preset loading). G-code changes slightly in places.

Fixes:
- Project presets now survive re-opening a project and switching printers.
- Bambu fan speeds no longer read 0 percent; the printer error popup fits its text.
- FlashForge Creator 5 no longer crashes the Device tab.
- Multi-tool printers switch off a tool's heater after its last layer.
- macOS: no crash just after launch, and the preview shows toolpaths on a busy Mac.
<!-- /update-notice -->

Everything in [2.4.4.2](https://github.com/aceRage/EdgeSlicer/releases/tag/v2.4.4.2-edge) is included.

## New

- **New G-code preview on libvgcode** (#369, #370, #372). The preview now renders through libvgcode (PrusaSlicer 2.8's viewer, as OrcaSlicer ported it). It was done in three stages. #369 replaces the G-code processor with OrcaSlicer's (Marlin planner kernels, per-move times, G2/G3 arcs timed as short segments); #370 makes the app ask for an OpenGL core profile; #372 swaps the viewer.
  - **New views:** Actual speed, Actual flow, Acceleration, Jerk and Pressure advance, each with a range legend, and an actual-speed profile in the tool-position window.
  - **Dim lower layers** (Preferences > General) with a brightness setting, and a **Default preview view type** preference (Automatic, Last used, or a fixed view type).
  - **Memory.** libvgcode needs about 40 bytes of graphics memory per vertex where the old viewer needed about 300 per segment. The PR's own benchmark converts 2 million moves to vertices in 77 ms; we have not timed the preview against the old viewer on real models. When memory does run low while slicing, the preview now loads a per-layer summary (legend, layer times and slider, no toolpaths) instead of nothing.
  - Kept from the old viewer: the cost breakdown, phone and remote previews, over-support colours, all-plates statistics, G-code viewer mode, and mixed-filament colours.
  - **G-code is byte-identical** to the old viewer on the cases the PRs compared (X1C, U1, MK4, H2C; one and two filaments, arc fitting). Estimated times do change, see Behaviour changes.
  - Upstream pieces taken with it: the Default preview view type, the tall-model scene-box fix for G-code viewer mode, and the layer-time and legend host changes. Upstream's scene/overlay split, SSAO colours, section view and realistic-view shadows are not included (their library halves are vendored, the host parts wait).
- **OpenGL core profile** (#370). The app asks for the highest forward-compatible core profile (4.6 down to 3.2) and falls back to the compatibility profile if none is granted. Set `EDGESLICER_OPENGL_PROFILE=core|compatibility|default` or `opengl_profile` in the app config to force one; if the shaders fail in a core profile the app writes `compatibility` and asks for a restart. The log gains start-up checks and one line per GL error, at most 40 per session. Wide and dashed lines are now drawn by a thick-line shader.
- **Costs** (#358, #363, #371).
  - **Cost breakdown after slicing** (#358): per filament (model, support, flush and tower split), the machine time cost, and a total, behind a `[+]` next to the cost in the preview. The all-plates view adds up each plate. A reopened sliced 3MF shows its cost instead of 0.00.
  - **Your own costs** (#363): one **Costs** window (Preferences, the Costs menu entry, and buttons on the filament and printer tabs) for filament prices per kg and machine rates per hour, applied over every preset without changing the presets. Filament prices are keyed by vendor, type and family, so one price covers every printer variant; machine rates are keyed by printer vendor and model, with a default rate. A currency symbol preference is used everywhere.
  - **Project tab** (#371): markup (percent or flat, of material or total cost), assembly time and rate, and fees per object, per part, per plate setup and per plate packaging, each with a "Use Default" toggle and an Applied Cost column. The breakdown shows the fee lines, **Markup** and a **Selling price**. Fees and markup are saved with the project and never reslice.
  - **Include costs in exported G-code** preference, off by default (see Behaviour changes).
- **Texture displacement** (#368, port of OrcaSlicer #14662 and #16148). Layer image textures onto a part as displacement, with a UV editor, preview, seams and bake. Layers, textures and paint are saved in the .3mf, so unbaked layers survive a save. Guards ask before a bake replaces a text or SVG part, and drop a CAD exact body that no longer matches. Colour is off by default and disabled while a mixed filament is enabled. The Export Bambu 3MF path leaves the texture data out. An older EdgeSlicer opens such a project with the unbaked surface and no texture.
- **Trace a PNG or JPG into multi-colour embossed shapes** (#362). Add part, Negative part, Modifier or Add Primitive > **Image...** (and Import image... in the SVG tool) opens a trace dialog: 1 to 8 colours (4 by default), threshold, smoothing, speck removal, resolution, width, depth, project onto surface, a filament per colour, and optional stepped relief. Each colour becomes one ordinary embossed SVG part; **Edit trace...** reopens the dialog. Dropping a .png/.jpg on the 3D scene asks: trace to shapes, relief (greyed out, coming soon), or colour fill (Image Fill).
- **Printers tab** (#361). An always-present **Printers** tab replaces the Multi-device tab slot: one card per printer with its picture, status, job and progress, temperatures, fans, filament and any error, with Pause, Resume and Stop (Stop asks first). It refreshes every 10 s while visible and does not depend on the printer preset or the multi-machine preference. The old Multi-device send pages open in a "Multi-device tasks" window.
- **Printer Selection as one table** (#356). "Select/Remove printers" and the setup wizard's printer page are now one spreadsheet-style table for all brands: Enabled, icon, Brand, Model, X, Y, Z and Toolheads columns that all sort and filter, plus a search box. The dialog is resizable.
- **3D move and rotate handles for the Text, SVG and Image tools** (#378). Arrows move the part along its own axes (or the world axes with a checkbox); red and green rings tilt it; the existing in-plane ring is now blue. A Placement line says whether the part is on the surface. Lifting, pushing or tilting a part that uses the surface turns Use surface off; the next surface drag puts it back. The handles can be switched off in the tool window.
- **Snapmaker U1 profiles** (#387). Nine Snapmaker-brand filaments (PET, PETG Basic, PLA, PLA Eco, PLA Lite, PLA Metal, TPE, TPU 95A, TPU High-Flow) from OrcaSlicer #16043 / #12824 under our `@U1` names, with pressure advance off; the mixed-nozzle machine **Snapmaker U1 (0.4+0.6 nozzle)** with a matching process preset (prime tower off, because a tower cannot span two nozzle diameters); sync of the nozzle sizes from a connected U1 picks the right machine variant; and Klipper acceleration is capped by the lower of the extruding and X/Y limits. Nothing here has been tried on a printer.
- **OrcaSlicer ports.** Batches from the catch-up plan, one upstream PR per commit, each adapted to this tree (items we skipped as already fixed or not applicable are listed in the PRs):
  - **1A, core crash, UB and hang guards** (#367): 17 of 21 upstream PRs (Arachne beading, multi-material segmentation, tree-support divisions by zero, `G1 F-2147483648`, cancel during interlocking, `cut_mesh` leak, flow-variant calibration guards and more).
  - **1B, GUI crash guards** (#365): 21 ported, 2 of them partly (PartPlate stale instance ids, filament map bounds, measure gizmo, Slice all with no stats item, exit use-after-free, 3MF dialog cancel, calibration cancel, prime tower rotate and others).
  - **1C, app robustness** (#366): 9 ported (16 MB worker thread stack, SIGPIPE ignored, locale fallback, out-of-memory dialog, ReleaseDC leaks, single-instance activation no longer maximizes, macOS quit-from-Dock crash, garbled Chinese ZIP names).
  - **1D, preset and per-variant load** (#384): tests for the load paths of upstream #13316 and #14106, and the code of #14103 (stale filament and extruder ids after a printer switch).
  - **2D, slicing geometry** (#380): 19 upstream PRs on Arachne, contours and infill (see Behaviour changes).
  - **3A, support quick fixes** (#379): six PRs (missing support layers, tree support collision with the bed, frozen fill thresholds, base ordering, organic bottom interface, tree base trimming).
  - **3B part 1, tree and organic supports** (#383): upstream #14069, #14092, #14040, #13192 and #13454.
  - **4A, pressure equalizer and cheap performance** (#386): #11249, #12575, #12063, #11887 and the remainder of #16028.
  - **Small ports:** #347 (no PrintConfig copies in simplify and tree-support helpers), #348 (holes in internal-bridge areas), #349 (LAN help image for unknown printer types), #351 (cheaper G-code post-process writer), #352 (one-wall-top keeps inner walls of narrow Arachne walls).
  - **#388, variant-aware normalize.** Printer presets in the per-extruder-variant layout (Bambu H2D, H2C, X2D and Klipper toolchangers such as MyToolChanger) kept only the first few of their per-variant retraction values. They now keep all of them, and the G-code reads one value per tool. H2D, H2C and X2D slice with the same G-code as before.

## Behaviour changes

- **Estimated print times go up** (#369). The processor now times each G2/G3 arc as the firmware's chain of short segments, and uses Marlin's planner. Measured on the PR's cases: +0.2 to +1.4 percent for most (X1C and U1 cubes and Benchy, MK4), +0.7 percent for two-filament plates, and +4.35 percent on an H2C Benchy, which has 1,469 spiral lifts (45 min 46 s before, 47 min 45 s after). Almost all of it comes from spiral lifts and arc-fitted perimeters; the planner rework alone is at most +0.2 percent. Whether the printers really corner small helices that slowly was to be checked by comparing real print times; we have not seen that result. The G-code itself is unchanged, apart from the U1's preheat `M104` lines, which are placed from the estimate and so move a little.
- **Preview changes** (#372, #370).
  - Hiding a single tool or colour from the **Filament** legend is gone (upstream dropped it too). Line type and option toggles still work.
  - Slider layers are the tagged layers, so a ContourZ or ZAA surface riding above its layer no longer adds layers.
  - Lines wider than 1 px that were not moved to the thick-line shader are 1 px on core: advanced-cut connection lines, height-limit lines, painter cut contours, travel lines. Dashed gizmo connection lines are solid.
  - **Compatibility profile on a Mac:** libvgcode needs OpenGL 3.2 core. With `EDGESLICER_OPENGL_PROFILE=compatibility` (the Mac's legacy 2.1 context) the preview is empty and a dialog says so. Leave the profile at its default on a Mac.
- **Costs are left out of exported G-code by default** (#358, #363). "Include costs in exported G-code" is off by default. With it off, the exported G-code, sent files and sliced .gcode.3mf carry no `; filament cost` / `; total filament cost` lines and no `filament_cost` or `time_cost` in the config block; project saves keep their prices. A G-code opened on its own then shows "not in file" instead of a cost (and "machine rate not in file"). Turning it on gives the G-code as before. `time_cost` edits now reslice only the G-code export.
- **G-code changes from the OrcaSlicer ports.**
  - **2D (#380):** internal solid infill grows 0.3 to 0.5 percent in length on parts with internal solid (20 mm cubes +0.33 percent, Benchy +0.52 percent) from the wider solid-infill area next to narrow regions (#12770). Slice contours lose the redundant point where a plane crosses a planar quad's diagonal (#15316, #15366), so curved or faceted meshes change slightly in most layers (Benchy outer wall +0.012 percent, Voron cube +1.3 percent); cubes are unchanged. Classic-generator gap fill changes (Benchy +0.46 percent). Other changes: non-line internal solid patterns isolate narrow regions (#12107); multiline density now applies to adaptive cubic, support cubic and lightning (#10967); adaptive infill connects to walls at low density (#11728); infill rotation templates work with a raft (#14894); the bridge density limit is 120 percent (was 100) and shrinkage compensation is limited to 50 to 150 percent (every shipped profile is inside). No case in the 60 compared was byte-identical to before. Left out on purpose: the inverse hole direction (#12669) and the Cross Hatch change of #12062, which would have lengthened internal bridges by 11 percent on default Bambu profiles.
  - **1A (#367):** Tree Slim, Strong and Hybrid support infill on non-bed layers now uses the pitch of `support_base_pattern_spacing` plus the flow spacing (what normal supports already did), which makes that infill about 16 percent sparser at the default 2.5 mm. This is the upstream fix (#11084) for a zero-pitch hang; it is its own commit, so it can be dropped.
  - **3A (#379):** non-organic tree supports (Strong, Hybrid, Slim) lose base material that sat too close above the model (#14128; for example 100 layers of support differ on an MK4 Benchy, from Z 9.8 up). The print order of support base paths changes (#11761), which moves a few start points, including the first-layer brim loop. Normal supports no longer vary between runs (the baseline gave two different files in 5 runs; 5 of 5 are now identical).
  - **3B part 1 (#383):** organic supports move about 1 percent in length on every layer; build-plate-only organic supports now get interface layers; tree tips follow overhang edges all the way round; **Tree Hybrid without a raft gets a 2 mm first-layer flange** under its normal-support areas by default (`raft_first_layer_expansion`, and `raft_first_layer_density` is now editable for every tree style).
  - **4A (#386):** with **extrusion rate smoothing** on, speeds around smoothed lines change: lines may now reach their set speed (peak F rises on some lines, falls on others) and are split into different segment counts. Total extruding time moves by -0.2 to +0.1 percent. Smoothing is off in every bundled profile and untested on a printer. The other 4A changes leave the G-code identical (17 of 17 compared).
  - **#348:** layers with an internal bridge over a hole get fewer stacked internal bridges. **#352:** narrow walls next to a top surface keep their inner walls with One wall on top.
- **Multi-tool printers switch off an unused tool's heater** (#113, from OrcaSlicer #15849, which is still open upstream). When a tool is parked and never used again, the G-code now has `M104 S0 T<n> ;cooldown` instead of the standby temperature. **This is the default on the Snapmaker U1**: all 18 of its process presets turn ooze prevention on, so every tool except the last gets `S0` instead of `S70` at its final toolchange. It does not apply to Bambu printers or to printing by object. Checked by tests and slices only; not tried on a printer.
- **Snapmaker U1 defaults** (#387).
  - New installs and re-run wizards pick the **0.4** machine with 0.4 on all four heads (they landed on the 0.2 machine before, because the first of the sorted variants was activated). Other makers' models that have a 0.4 variant now start on it too.
  - **Pressure advance is turned off** in 18 existing U1 filament presets that had it on (16 files: Snapmaker ABS 0.4/0.6/0.8, ASA base, PETG HF, PETG Translucent, PETG-CF, PLA Full Spectrum, Glow, Matte, SnapSpeed, Translucent, Wood, PLA-CF, PVA, Support For PLA). None had it in its filament G-code. Slices with those presets no longer use the printer's pressure advance.
  - `Generic PETG HF @U1` 0.2, 0.6 and 0.8 now print at 230 C (was 220 C). `Snapmaker PETG @U1` still resolves to `Snapmaker PETG HF` (alias kept).
  - Klipper acceleration is capped by the smaller of the extruding and X/Y limits. The U1 has equal limits, so its G-code does not change; other Klipper printers with X/Y limits below the extruding limit now honour the lower one.
- **macOS memory guard** (#372, #381). The low-memory check read macOS "available" memory as free pages only, so on a busy Mac it fired about a second into every slice, and continuing skipped the toolpaths (the old viewer drew nothing either). Available memory is now free plus inactive plus purgeable pages, capped at physical memory. A guard that fires no longer decides the preview: the toolpaths load unless moves times 256 bytes plus 256 MB headroom exceeds what is available, and the per-layer summary is the last resort, with a warning notification and a "Memory is low: toolpaths not loaded" legend line.
- **Project presets and "Keep my printer"** (#357). Opening a project that uses project presets a different printer cannot use no longer switches to your last printer: the project opens on its own printer with an info notification. A switch the parent profiles cover (such as X1C to P1S) still happens. Filament presets saved to the project are no longer pinned to the one printer they were saved on.
- **Printers tab replaces the Multi-device tab** (#361). The tab no longer depends on the printer preset's vendor or the `enable_multi_machine` preference.
- **Image drops** (#362). Dropping a .png/.jpg on the 3D scene now asks what to do with it: trace to shapes, relief (not available yet) or colour fill.
- **Bambu fans** (#353). Setting a fan on an H2-series printer sends Bambu Studio's `set_fan` (percent); other printers keep `M106`.
- **Preset load log** (#389). Every start logged about 2,200 `[error]` lines for four keys that bundled presets carry and presets do not hold (`filament_flush_temp`, `filament_flush_volumetric_speed`, `filament_cooling_before_tower`, `mixed_filament_definitions`). They are dropped as before and reported once, as an info line with counts. Values and G-code are unchanged. The keys are not ported; they would matter for H2D, H2C, H2S, P2S and X2D (we emit `M620.15 C` 10 degrees hotter than Bambu Studio) and that needs a printer check.

## Fixes

- **Project presets disappeared** (#357). Presets saved with Save to project went missing when the project was opened again: "Keep my printer" (on by default) switched to your last printer and deselected every preset that printer could not use, and project filaments were pinned to the one printer they were saved on. Both are fixed (see Behaviour changes). The Save Preset dialog has a new **Use for every printer** checkbox for process and filament presets saved to the project: it gives the preset an empty printer list, so it is listed for every printer and stays selected across switches. It is off by default and the 3MF format is unchanged; an older build shows such a preset on every printer. Checked with round-trip tests on the real BBL profiles.
- **Text and SVG tools were hard to grab** (#377). With the tool open only the glyph strokes grabbed, so a press between letters hovered the object behind, closed the tool and moved the whole object. The part's on-screen footprint (its projected convex hull, padded by 6 px) is now the grab zone, so the surface drag starts anywhere in it. Outside the tool, a text or SVG part now wins the pick over the surface it is slightly sunk into, within its own emboss depth (0.1 to 3 mm), for hover, click, double-click and Alt-click. A plain click records no undo step. Also from OrcaSlicer #15095: releasing the mouse over the scene after selecting text in the tool no longer closes the tool or selects a plate.
- **Bambu fan speeds read 0 percent** (#353). On X1C and H2S the Device tab showed every fan at 0 percent and the phone app 0 or 2 percent while printing, because the new-protocol `device.fan` field (values 0 to 7) overwrote the real 0..255 values. It is no longer read. H2-series fans come from `device.airduct`, and Aux and Chamber fans on those printers are listed without the `support_*_fan` flags. Not yet checked on hardware when the PR merged.
- **Printer error popup** (#354). The Bambu printer error dialog was too small: the message was clipped behind a scrollbar, the buttons crowded it, and the error code appeared twice. It now sizes to its content (scrolling only past 420 DIP or 55 percent of the screen), the buttons fill the width, and the code is shown once. Not seen on screen when the PR merged.
- **FlashForge Creator 5 crashed the Device tab** (#318, Sentry EDGESLICER-6). A printer added by IP, serial and check code started with an unknown model (pid 0); the temperature panel built no rows and then dereferenced a missing one. The printer's own reported model now wins, the panel looks rows up safely and is rebuilt when the model becomes known, and an unknown model gets read-only generic rows with no temperature command sent. A Creator 5 or 5 Pro on this path gets its proper four-nozzle layouts and appears in the send dialog's device list.
- **macOS crash about 2 seconds after launch** (#375). The background-process timer could fire during the splash, before the main frame existed, and `BackgroundSlicingProcess::apply` dereferenced a null main frame (EXC_BAD_ACCESS in Sentry minidumps). The timer now re-arms until the frame exists and `apply` reads the plater null-safely.
- **macOS preview and GL errors** (#372, #385, #381).
  - No toolpaths after any slice on a busy Mac: see the memory guard under Behaviour changes.
  - `GL_INVALID_ENUM` in every thumbnail: depth renderbuffers are now sized (`GL_DEPTH_COMPONENT24`), which macOS core requires.
  - #385 (after a second Mac test): a leftover `GL_INVALID_ENUM` from a point-size query is gone (confirmed on the Mac). The libvgcode segments program left a 2D sampler and a buffer sampler on texture unit 0 until its first draw, and its shadow map had no texture; both are fixed, so is ImGui's font texture being deleted mid-frame and the select-plate toolbar being built twice per canvas. The owner's second Mac retest (build 3abad9160c, `EDGESLICER_GL_DEBUG=1`) passed: Apple's `unit 0 GLD_TEXTURE_INDEX_2D is unloadable` message is gone both after a slice and in G-code viewer mode, `ImGui: skipped a draw with texture 0` is gone, there are no `OpenGL texture check` lines and no thumbnail framebuffer error, and the log says the first Preview frame rendered without GL errors. That was one Mac (8 GB A18 Pro, macOS 26.6.2). New `EDGESLICER_GL_DEBUG=1` and `EDGESLICER_GL_SKIP=<part>` diagnostics are there if it shows up elsewhere.
  - #381: the Mac build failed after #372 (`get_physical_memory()` should be `total_physical_memory()`).
  - #382: Xcode 26 / clang 21 rejected out-of-range `wxMediaState` constants; they now have runtime initialisers.
- **Image Fill crash with several threads** (#376). `ImageAssetStore::pixels()` marked an asset decoded before filling its size and pixels, so a second fill thread could read a half-built image (a SIGSEGV seen in `test_image_row_transform`). The decode now runs under a mutex. A new stress test fails on the old code 5 of 5 times and passes 20 of 20.
- **Linux and Flatpak build** (#374). `UVEditorCanvas.cpp` called `wxBitmap::GetLogicalSize`, which our wxWidgets fork lacks; it now uses `GetScaledSize()`.
- **Cost tests** (#373). A Windows test cleanup no longer throws when a virus scanner holds a just-written file, and tests stop leaving temp directories behind.
- **LAN help image** (#349). The Bambu LAN "input IP" dialog no longer asks for an image named `_en` when the printer type is unknown; a Debug build no longer asserts there.
- **Crash and robustness guards from OrcaSlicer** (#365, #366, #367, #384): see New. Notable ones for users: Slice all with no stats item, quitting with a model selected, cancelling the 3MF or calibration import dialog, switching printers with stale filament or extruder ids, quitting from the macOS Dock, a locale that is not installed, garbled Chinese ZIP entry names, and (Windows) running out of memory now showing a dialog.

## Known limitations and not tested

- The Mac test rounds for #372 and #385, including the passing round-2 retest, were all run on one Mac (8 GB A18 Pro, macOS 26.6.2, GL 4.1 Metal); other Macs, GPUs and drivers are untested. If the preview is blank or a dialog says libvgcode needs OpenGL 3.2, set `EDGESLICER_OPENGL_PROFILE=default` or `core`, and send the log.
- No print was made to compare the new time estimates with the printers' real durations.
- Not tested on a printer: the Snapmaker U1 filaments, the 0.4+0.6 machine and the nozzle sync from a connected U1 (#387); the multi-tool heater change (#113); extrusion rate smoothing (#386); the Bambu fan and error-popup fixes (#353, #354, when they merged).
- Not verifiable on Windows, so not tested here: the Mac-only and Flatpak items in batches 1B and 1C (macOS quit from the Dock, the assembly-mode Flatpak guard), and the Linux GTK build fix (#374), which comes from the CI log.
- Texture colour with mixed filaments is not supported. The PNG trace does not apply JPEG EXIF rotation (phone photos may come in rotated), does not read BMP, and has no Bezier fitting yet. Relief in the image drop chooser is greyed out.
- Hiding one filament in the preview legend is gone for good (see Behaviour changes).
- Still open and not in this release: Snapmaker #962 port (keep per-volume settings when adding a 3MF, #350), the inverse hole direction (OrcaSlicer #12669), and the remaining batches of the OrcaSlicer catch-up plan.

## Under the hood

- **libvgcode** is vendored at `src/libvgcode` (OrcaSlicer 78f74a6276). The viewer host is OrcaSlicer's `GCodeViewer` and `LibVGCodeWrapper` from c833ccdf6f with EdgeSlicer's features re-ported. The processor adds per-move pressure advance, acceleration and jerk, and flags actual-speed points (Slice Compare skips them). The old time tables are recomputed from per-move times so `slice_info` keeps its meaning.
- **Tests** merged with their PRs: processor times, arcs and actual-speed points (#369); a headless core-profile smoke test that opens a hidden GLFW window and draws through GLModel, plain VBOs, the thick-line shader and libvgcode (#370, #372, #385); libvgcode input and layer times, memory-guard policy with fake `vm_statistics` and meminfo (#372); cost estimate, overrides, pricing and slices (#358, #363, #371, #373); project preset round trips (#357); emboss picking and free-transform rules (#377, #378); image trace (#362); texture displacement, paint remap and undo (#368); FlashForge pid rule (#318); Bambu fans (#353); printers monitor and its headless page gate (#361); image-asset stress test (#376); NozzleSync, U1 profiles and the Klipper acceleration cap (#387); extruder-variant normalize (#388); foreign preset keys (#389); and the port batches' own cases.
- **Costs store** (`<datadir>/cost/filament_overrides.json`) is schema version 3: `filament`, `machine`, `machine_default` and `pricing`. Older files are read and rewritten; unknown fields are kept. Project pricing is saved as `edgeslicer_pricing` metadata in project saves and backups only, never in G-code, Bambu exports or sliced-plate files.
- **Window and module notes:** `PrintersPanel` and `RemoteAccess::monitor_*` (#361); `libslic3r/PrinterModelSpecs` for the table's sizes and toolheads (#356); `libslic3r/ImageTrace` and `CostEstimate` have no wx dependency; `PresetBundle::default_printer_variant` and `variant_to_activate` (#387); `resolve_printer_extruder_variants` runs at the top of `Print::apply` (#388).
- **Under #386**, `ResolvedFilamentFlow` now also resolves the process-domain slot per filament, so `_extrude` stops doing string lookups per read. Identical G-code (17 of 17), and no measurable speed change on the shared machine used for the PR.
