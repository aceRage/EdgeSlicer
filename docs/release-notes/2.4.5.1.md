# EdgeSlicer 2.4.5.1

<!-- update-notice -->
New in 2.4.5.1:
- Bambu Lab sign-in and cloud now work on macOS and Linux, and the browser ends on a clear "Signed in" page. Bambu's own network plug-in is never downloaded.
- Bambu X2D, P2S, A2L and H2D Pro are recognised over LAN (an X2D could not be sent to), and the X2D, H2D and H2C can use each extruder's external spool.
- Side stabilizers no longer need Enable supports.
- SVG (Split): one part per SVG shape, with a filament chosen for each colour. Every SVG import now asks SVG or SVG (Split).
- Mobile Hub on macOS and Linux: Tailscale remote access, camera video, firewall checks. A macOS Account menu.
- Export Preset Bundle shows process and filament presets as sortable, filterable tables.
- Bambu printers with a prime tower (H2D, H2C, H2S, X2D, P2S) now cool the nozzle before the tower and heat it back. More OrcaSlicer ports: first-layer speeds, support interface layers. G-code changes in places.
- Your presets are no longer synced to any cloud account; they stay on this computer.

Fixes:
- Command-line slicing no longer crashes when writing thumbnails or when several objects warn at once.
- A print you cancel is shown as cancelled, not failed.
- The log is much smaller: printer status pushes no longer fill it.
- Only one Mobile Hub runs per data folder.
<!-- /update-notice -->

Everything in [2.4.5.0](https://github.com/aceRage/EdgeSlicer/releases/tag/v2.4.5.0-edge) is included.

## New

- **Bambu sign-in and cloud on macOS and Linux** (UltraNet plug-in #8 and #9; app #416, #420, #422). The plug-in's cloud calls only worked on Windows, so signing in to a Bambu Lab account did not work elsewhere; they now work on macOS and Linux, using the system certificate store. Once the cloud session is connected it asks each printer for a full status. Checked on one Mac (8 GB A18 Pro, macOS 26.6.2): sign-in works.
  - **A result page of our own** (#420). The browser used to be sent on to Bambu's hand-off page, which tries to open Bambu Studio's URL scheme; on the Mac, Safari ended a successful sign-in on "address is invalid". The callback now shows "Signed in to Bambu Lab", or "Bambu Lab sign-in did not complete" with a short error code. The page has no script and loads nothing from outside.
  - **Account menu on macOS** (#410). The menu bar gets an Account menu (per-brand sign in and sign out, same entries as the Windows Account button) and the View menu gets Mobile Hub.... Checked on the Mac.
  - **Sign-in diagnostics** (#416). A failed ticket exchange or profile call now logs the HTTP code and a scrubbed excerpt of the answer (no ticket, token or e-mail address). A callback listener on a fallback port is a warning instead of a false "Google sign-in will fail" error.
  - **One ticket exchange per sign-in** (#422). A ticket is single-use; a repeated callback now gets the first answer instead of a second exchange that failed with HTTP 401. Requests without a ticket (favicon, preload) get a 404 and are not logged as logins.
- **Bambu X2D, P2S, A2L and H2D Pro** (#409). An X2D could not be sent to over LAN: it announces model code N6, this build had no definition for it, and the send dialog showed an empty model and refused. The X2D (N6), P2S (N7), A2L (N9) and H2D Pro (O1E) definitions from Bambu Studio are added, and a printer is now identified by model code, then sub-series, then serial-number prefix. Saved LAN printers are re-identified on load. An empty model gets its own message ("Couldn't identify this printer..."). On the X2D bed, the bed-type tab no longer hangs off the front edge; the X2D 3MF now says `extruder_type="0 1"` (second extruder Bowden), as Bambu Studio writes it. The X2D's change-filament template had lost a leading `;`, so every tool change wrote a bare header line into the G-code; that is restored.
- **External spools on two-extruder Bambu printers** (#413). On the X2D, H2D, H2D Pro and H2C, each extruder's external spool holder (Ext-L, Ext-R) can now be used. An extruder with no AMS uses its holder automatically; the Filament arrangement dialog offers Ext-L and Ext-R; the send dialog's tray picker shows each filament's own extruder only (its AMS units and its holder); and the AMS-aware slice counts a loaded holder. The print message follows Bambu Studio's encoding for an external spool. An X2D user (AMS HT on the left, spool on the right holder) confirmed that this works.
- **Side stabilizers without Enable supports** (#406). Stabilizers generate and print with Enable supports off; nothing else about supports changes. Their options, and the support filament, speed and X/Y distance, stay editable while stabilizers are on. With supports off the only Support-role extrusions are the stabilizers: no interface, transition, tree or raft.
- **SVG (Split)** (#419). Add Primitive, Add part and the SVG tool's file menu get **SVG (Split)**: one editable part per SVG shape, painted in file order so later shapes win (a part is its shape minus what is painted over it), and a dialog that matches each SVG colour to the nearest project filament (CIEDE2000; colours far from every filament are shown in red, and **Add filaments for unmatched colours** adds them). The whole import is one undo step. The plain **SVG** import is unchanged. Tested on a 131-shape trace SVG: 66 parts, one per visible fill.
  - **Every GUI import of an .svg asks** SVG, SVG (Split) or Cancel: File > Import, Ctrl+I, the toolbar Add button, dropped files, recent files and Add part > Load.... Several SVGs in one import can share one answer. Negative volumes and modifiers stay plain SVG.
  - **The model loader behind the command line** now converts shapes like the SVG tool, with fill rule, holes and strokes. It used to garble multi-contour paths (5 of 66 fills wrong in the test file) and drop the stroke of a shape that also had a fill.
- **Export Preset Bundle as tables** (#407). Process presets(.zip) and Filament presets(.zip) show one row per user preset in a sortable, filterable table (printer, preset, layer height or vendor and material, last modified), like Printer Selection. Resizable dialog with remembered size, draggable column widths (Printer Selection gets this too), search, per-column filters, and ticks that persist across filters. The other three export modes are unchanged.
- **Mobile Hub on macOS and Linux** (#417, #418). Everything that was Windows-only has a counterpart:
  - **Tailscale** (#417): the CLI is found at the app's path, Homebrew and system paths, and run without a shell; a Tailscale interface on macOS (`utun`) is recognised. A `tailscale status` that does not answer says so instead of "not installed", and `tailscale serve` waiting on the admin console stops at once with the link.
  - **Camera video** (#418): go2rtc runs as a child of the hub. The macOS app bundles go2rtc; ffmpeg is never bundled, and a Homebrew ffmpeg is used as a fallback for quality variants (hardware H.264 on a Mac, then OpenH264, then x264).
  - **Firewall checks** (#418): read-only, never changes anything. macOS reads the application firewall (off, on, block all, EdgeSlicer blocked or not yet allowed); Linux reads ufw and firewalld. No `netsh` text off Windows.
  - Also: the port holder is named, TCP keep-alive works, the LAN link lists the Wi-Fi address first, tray notifications use the system notification, and the Funnel note shows the Tailscale path that was found.
  - Passed on the Mac: Tailscale detection, remote access on and off with the phone, the Tailscale-stopped message, go2rtc start, quit and orphan clean-up, phone live video, port holder, notification, LAN link, and the block-all firewall wording (it failed first, was fixed, and passed on the recheck). A combined Mac check also passed go2rtc bundled with WebRTC on 8555, Tailscale remote access, the camera, and an H2C send and print.
- **OrcaSlicer ports** (more of the catch-up plan).
  - **2A, writer, travel and layer-change correctness** (#390, follow-ups #408): 16 upstream PRs (see Behaviour changes).
  - **3B part 2, support interface semantics** (#395): upstream #11812, #14678, #15525, #15539 and #15565, plus the #15575 tests (see Behaviour changes).

## Behaviour changes

- **Prime-tower toolchanges on Bambu printers cool, then reheat** (#392). Bambu's per-filament `filament_flush_temp`, `filament_flush_volumetric_speed` and `filament_cooling_before_tower` (and the new `filament_flush_temp_fast`) used to be dropped on load, so every Bambu change-filament template ran on defaults. They are kept now, with a Wipe tower cooling field (Develop mode) and flush temperature and speed fields in the filament's Multimaterial page. On the H2D, H2D Pro, H2C, H2S, X2D and P2S, every tower toolchange after the first layer now has `M620.15 C` 10 degrees below the new filament's print temperature (PLA 220 + PETG HF 245 on an H2D: C210 and C235, not C220 and C245), and the tower writes `M104 T<extruder> S<print temp> N0 ;Wipe tower reheat before wipe` before the new filament's first tower extrusion, as Bambu Studio's tower does. On the checked slices every cool-down has its reheat (H2D 99 of 99, H2C with rack nozzle changes 198 of 198). Also changed: 17 PLA Silk and P2S PETG HF presets change their flush temperature, the 0.2 mm nozzle presets their flush speed, and A2L presets that set cooling (PETG Matte, TPU 85A 0.6 and 0.8) change their SYNC heat-up compensation. X1, P1, A1 and non-Bambu printers: no G-code change. The first version of this change cooled to 210 but never heated back (found by the owner printing on an H2D); the fixed version, with the tower reheat, was printed on the H2D and the owner confirmed it works.
- **G-code changes from OrcaSlicer batch 2A** (#390, #408). Measured in the PRs' CLI gates (29 slices per build).
  - **First layer speeds.** Support, support interface, support transition and the raft base on the first layer print at Initial layer speed, like walls and the brim. Gap infill and the other infill roles on layer 1 use Initial layer infill speed (U1 and X1C 0.20 Standard: gap infill 50 to 105 mm/s). The first object layer over a raft takes first-layer speeds, with no overhang slow-down or fan split on that layer, and the raft ramp starts at that layer. Support printed on the first object layer over a raft is unchanged. The wipe after a changed move gets shorter or longer with its speed.
  - **Z after a toolchange or custom G-code** goes to print Z plus Z offset, not the bare layer Z (U1 with a 0.1 mm Z offset: `G1 Z.25` becomes `G1 Z.35`). A pending layer-change lift is synced to the path's own start Z.
  - **Short travels before outer walls** (shorter than the minimum travel to retract) keep the outer-wall acceleration and jerk, so one acceleration line per wall start disappears. Acceleration and jerk are re-emitted after custom G-code that sets them.
  - Holes up to 0.2 mm (was 2 mm) are dropped from the avoid-crossing boundary. The brim uses Initial layer speed. Spiral vase drops very short segments (vase Benchy only). Per-object skirts with a draft shield and interlaced support layers are extruded at the object's layer height (a case that printed twice the flow before).
  - **Settings checks.** G92 E0 must be exact upper case in relative mode, and the absolute-mode checks also run for Bambu (no shipped profile fails them; only a hand-edited lower-case or absolute-E Bambu config is refused). Wipe with firmware retraction is valid at 100% retract before wipe (the dialog only appears below 100%; answering Yes still turns Wipe off, as upstream). Preheat lines in the processor also need ooze prevention (all 18 U1 processes have it). The default output name uses the project's 3MF name. A layer height outside the printer's limits now offers Adjust or Ignore, and Ignore sticks (nothing clamps it afterwards); the same check now covers Initial layer height, in the print tab and in per-object settings. "Top Z distance overrides X/Y distance" greys out with supports off.
  - **Removed or changed options.** `tree_support_adaptive_layer_height` is gone (old files drop it silently), and Independent support layer height is a normal support field. Layer height profiles are bounded by the uncompensated height.
- **Support interface layers change** (#395). All taken from upstream's current behaviour (Benchy, CLI, default profiles).
  - **Interface layer count is exact.** N configured top interface layers print N; before, the contact layer came on top (N+1). Normal support Benchy: 122 to 101 layers with interface, interface length -29 percent.
  - **Build-plate-only classic trees print far fewer interface layers.** Floor patches on the side of the model below a branch are gone (Benchy strong, slim, hybrid: 50 to 10 layers with interface); the real roofs still get N layers.
  - **Top Z distance 0 no longer means soluble by itself.** Zero-gap contact needs interface layers. With a different interface filament, one of the configured interface layers is now a base-material transition layer (U1 T4: interface-filament layers 2 to 1).
  - **Bottom-only interfaces print** (top interface layers 0, bottom above 0), and Bottom interface spacing is used.
  - **Interface line angle is constant per layer** for Auto and Rectilinear (it used to alternate 45 degrees); Rectilinear Interlaced alternates and Grid crosses.
  - Organic supports: bottom contacts no longer eat a bottom interface layer. Organic and classic trees are now deterministic (same G-code every slice, any thread count); organic geometry moves by a few percent once. Classic trees with Independent support layer height were not deterministic before.
  - Of 69 support cases compared, 67 differ and 2 (no interface) do not; 13 no-support cases are byte-identical.
- **Stabilizers and spiral vase** (#406). Slicing is refused with "Spiral vase mode can't be used with side stabilizers", supports on or off. Before, supports on, stabilizers and spiral gave a broken vase. Support filament matching and flush-into-support still do not apply to stabilizers alone.
- **Brim around stabilizers** (#406). With supports off, the brim keeps out of the stabilizer pillar footprints, as it does with supports on.
- **User presets stay local** (#414). Presets (printer, filament, process) are no longer synced with any cloud account. The sync thread never starts, the Auto sync user presets checkbox and the Sync user presets button are gone, and deleting a preset no longer queues a cloud delete. Files in `user/default` and everything saved with them are untouched. This also stops a loop that asked the Bambu cloud for the same ~590 presets' ids every couple of seconds (about 5,600 calls per log file).
- **Bambu's network plug-in is never downloaded** (#415). Every place that offered, prompted for or performed the Bambu CDN plug-in download now shows "EdgeSlicer's network plug-in is missing, so Bambu Lab sign-in and printing are unavailable. Reinstall EdgeSlicer to restore it." The plug-in shipped with EdgeSlicer stays silent. Staged update packages are never installed. The Windows camera component offer (BambuSource) is left as it was.
- **Log levels** (#412). At log level Info, printer status pushes no longer log. The full payload (about 97 MB of one 108 MB log file) moves to trace; non-push messages get a one-line summary. Several per-push repeats move to debug or trace, or log once per printer and type. Warnings, errors, connections, print start and finish, HMS and command acks are unchanged. Debug restores the preset-sync and task lines; trace restores payloads. The code default is warning, so only installs set to Info saw the spam.
- **Cancelled prints** (#422). A Bambu print you cancel is a `cancelled` event (quiet, info severity), not `failed` or `error`. A FAILED state with no reason yet is held up to 10 seconds for its code, so a real failure is reported 5 to 10 seconds after the printer reports it. Klipper and PrusaLink cancels were already cancelled.
- **One hub per data folder** (#393). The hub takes an exclusive lock before anything else; a second hub for the same folder exits and logs why. The slicer remembers the hub it spawned and waits for it instead of starting another (it ends its own child at 120 s). The Device tab retries loopback page errors with back-off (about 23 s) and no longer logs them as fatal. Hubs from older builds do not take the lock, so an old and a new hub can still overlap.
- **Tray picker on two-extruder Bambu printers** (#413). The tray picker shows only the filament's own extruder; before, the other side could be picked and Send was then blocked with "wrong extruder".

## Fixes

- **Command-line thumbnails crashed** (#411). Every command-line slice that rendered thumbnails ended in a segfault after the G-code was written, because the camera read the app config with no GUI. It now works without one; 24 of 24 runs on X2D, X1C, H2D and U1 wrote the G-code and the 3MF with all thumbnails. `--no-thumbnails` is no longer needed.
- **Command-line status race** (#396). Several objects raising the "enable support" warning at once could corrupt the heap (a crash or hang in 5 of 60 runs under load, none in 200 after the fix). The GUI was never affected.
- **Stream tab icon 404** (#422). The Stream tab no longer logs an error for its missing icon.
- **Camera page script error on Mac** (#418). The Bambu custom-camera script in the Device tab now waits for the video element before setting its attributes, which removes a console error.
- **Cancel shown as failure, duplicate sign-in exchange, X2D send**: see Behaviour changes and New.

## Known limitations and not tested

- **Not tried on a printer:** the X2D, P2S, A2L and H2D Pro definitions and the X2D slice_info (#409; the author had no X2D, and the `extruder_type` and template fixes are marked likely, not confirmed), and the tray encoding for other two-extruder printers (#413; only the X2D case was confirmed by an X2D user). No result is recorded for the U1 confirmation print listed in #390.
- **Support interface, accepted as upstream** (#395, found on a crown model; the owner checked the GUI side and accepted these as upstream behaviour).
  - Organic supports put no interface roof on a slope when the tree tip is thin: below about 1.13 mm tip diameter the tip does not carry the roof (a crown with 1.0 mm tips got none; 1.2 mm gave interface along the slope). Under a flat overhang organic prints exactly N layers. Workaround: raise Tree tip diameter to 1.2 mm.
  - Tree supports (slim, strong, hybrid) stop the interface where a layer's overhang island drops below 1 mm2, so on a tapering slope the interface ends about 2 mm lower than with normal supports (17 layers at 0.12 mm); the base support continues.
- **Checked by hand by the owner and passed:** batch 2A and its follow-ups (#390, #408; GUI checks including the layer height dialogs and first-layer speeds), support interface batch 3B part 2 (#395), stabilizers without supports (#406), the Export Preset Bundle tables (#407), SVG (Split) through every import route (#419), and the cancel and sign-in follow-ups (#422; one cancel alert, the remaining "failed" alert in that test came from an older test copy running alongside). The sign-in result page (#420) was checked on the Mac and on Windows (Google sign-in).
- **Merged without a hand test:** the log level cut (#412), turning off cloud preset sync (#414) and the no-download rule for Bambu's plug-in (#415) were merged on the owner's say-so; their PRs list hand tests that were not run. Tests cover the decisions and models behind the GUI flows.
- **macOS and Linux items** were checked on one Mac only (8 GB A18 Pro, macOS 26.6.2): the Account menu (#410), the hub (#417, #418), the sign-in result page and ticket handling (#420, #422) and UltraNet sign-in. Not compiled or run on a Mac: the macOS CI step that downloads and bundles go2rtc (it has not run in CI yet, so the first release build is its test), the VideoToolbox ffmpeg template, and the exact output formats of `socketfilterfw --listapps` and `--getallowsigned` (parsed tolerantly; "not listed" is only claimed when the header is present). Linux hub code was compiled and unit-tested under WSL only. Linux has no go2rtc bundling, no pinned digests and no ffmpeg bundle. The Tailscale "Serve not enabled" prompt wording is from memory; the admin-console link rule is what is relied on.
- **Bambu plug-in message** (#415): the Windows camera component offer still downloads BambuSource and live555 from Bambu's CDN if you say yes.
- **A2L plate art** is not ported (it needs Bambu's ignore lists, which our profile lacks); it draws the single-nozzle art scaled to its bed. The A2L writes no `<nozzle>` tag in slice_info, as the A1, X1 and P1 do today.
- Still open from 2.4.5.0 and not in this release: the Snapmaker #962 port (#350), the inverse hole direction (OrcaSlicer #12669), and the remaining batches of the OrcaSlicer catch-up plan.

## Under the hood

- **Tests** merged with their PRs: Bambu flush keys and tower reheat (`[BambuFlushKeys]`, 8 cases, 96 assertions); batch 2A ports and follow-ups (`[Orca11011]`, `[Orca10722]`, `[Orca10942]`, `[Orca12937]`, `[Orca13327]`, `[Orca13224]`, `[LayerHeightCheck]`, first-layer speed cases); support interface counts, organic determinism and the zero top-Z static (`[SupportInterface]`, MST, tree smoke); stabilizers without supports (`test_stabilizers_without_supports.cpp`); Export Preset Bundle (`test_process_preset_export.cpp`, 245 assertions, and a 88-check headless page gate); device model codes and X2D areas (`[DeviceModelCode]`, `[X2D]`); external spool mapping (`[ExternalSpool]`, `[BambuSendMapping]`); SVG split and import routing (`[SvgSplit]`, `[SvgImport]`, `[SvgImportRouting]`); hub handover, Tailscale, platform parsers and addresses; plug-in guard and cloud sync policy; login diagnostics, result page and ticket gate; remote events; CLI thumbnails and the status collector; stream page icons.
- **Hub**: `HubHandover.hpp` and `WebLoadRetry.hpp` (#393), `TailscaleCli.hpp` and `HubPlatform.hpp` (#417, #418), all header-only with fixture tests.
- **Libraries**: `SlicingStatusCollector.hpp` (a mutex-guarded collector; the memory guard timestamp is atomic) (#396), `SvgSplit` and `SvgSplitDialog` (#419), `ProcessPresetExport` and `FilamentPresetExport` with the shared table engine `data_table.js` (#407), `PluginGuard` and `PresetSyncPolicy.hpp` (#414, #415), `LoginTicketGate` and `ResponseLoginResult` (#420, #422), `BambuExtruderMap` and `DualNozzleSync` external-spool slots (#413), `PartPlateList::init_bed_type_info` plate art (#409).
- **Profiles**: `printers/version.txt` is `01.10.00.03` (new `N6.json`, `N7.json`, `N9.json`, `O1E.json`), `BBL.json` is `02.00.00.78` (X2D template). Every shipped Bambu definition now carries its serial prefix.
- **GL test** (#394): the core-profile test now shares one GL context for the whole process. It looked hung when the machine was busy because the graphics driver was slow to create contexts; it finished in 3 s when quiet and over 400 s when busy. The product creates one context per canvas and is not affected.
- **Build**: the macOS CI job downloads the official go2rtc v1.9.14 zips, checks their pinned SHA-256, makes a universal binary and bundles it; Windows `.exe` and `.dll` files under `resources/tools` are left out of Mac and Linux packages.
