# EdgeSlicer 2.4.5.1

<!-- update-notice -->
New in 2.4.5.1:
- Fixed Bambu sign-in on macOS, improved landing page
- Recognises the X2D, P2S, A2L and H2D Pro, and two-nozzle printers can use the external spool.
- Side stabilizers without supports
- SVG (Split) and loading fixes
- Mobile Hub on macOS/Linux and a macOS Account menu
- Export Presets UI updates.
- More OrcaSlicer ports and catchup
<!-- /update-notice -->

Everything in [2.4.5.0](https://github.com/aceRage/EdgeSlicer/releases/tag/v2.4.5.0-edge) is included.

## New

- **Bambu sign-in and cloud now work on macOS and Linux** (#416, #420, #422). Signing in no longer ends on a browser error page: you get a plain "Signed in to Bambu Lab" page, or a clear message with a short code if it failed. A repeated sign-in callback no longer causes a second, failing exchange. Checked on one Mac (8 GB A18 Pro, macOS 26.6.2) and, for the Google sign-in page, on Windows.
- **macOS Account menu** (#410). The menu bar gets an Account menu (sign in and out per brand) and the View menu gets Mobile Hub. Checked on the Mac.
- **Bambu X2D, P2S, A2L and H2D Pro** (#409). An X2D could not be sent to over LAN because the app did not know its model. These four printers are now recognised (by model code, then serial number), saved LAN printers are repaired on load, and the X2D bed art and 3MF are corrected.
- **External spools on two-nozzle Bambu printers** (#413). On the X2D, H2D, H2D Pro and H2C each extruder's external spool (Ext-L, Ext-R) can be chosen in the Filament arrangement dialog and the send dialog, and is used automatically for an extruder with no AMS. An X2D user confirmed it works.
- **Side stabilizers without Enable supports** (#406). Stabilizers print with supports off, with no other support added.
- **SVG (Split)** (#419). One editable part per SVG shape, painted in file order, with a dialog that picks a filament for each colour. Every SVG import (File > Import, Ctrl+I, drop, recent files, Add part) now asks SVG or SVG (Split). The command-line SVG loader no longer garbles multi-contour shapes or drops the stroke of a filled shape.
- **Export Preset Bundle tables** (#407). Process and filament presets export from a sortable, filterable table with resizable columns; the other export modes are unchanged.
- **Mobile Hub on macOS and Linux** (#417, #418). Tailscale remote access, camera video (go2rtc is bundled on the Mac; a Homebrew ffmpeg is an optional extra), read-only firewall checks and notifications now work outside Windows.
- **OrcaSlicer ports:** batch 2A (writer, travel and layer-change fixes, #390, #408) and batch 3B part 2 (support interface, #395). See Behaviour changes.

## Behaviour changes

- **Bambu printers with a prime tower cool the nozzle before the tower and heat it back** (#392). On the H2D, H2D Pro, H2C, H2S, X2D and P2S, Bambu's per-filament flush settings are now used. Each tower toolchange after the first layer cools 10 degrees below the new filament's temperature (`M620.15 C`), and the tower reheats before the new filament prints (`M104 ... ;Wipe tower reheat before wipe`). A few flush temperatures and speeds change too. The first version cooled but never reheated; the owner found this printing on an H2D, and the fixed version was printed and confirmed. Other printers: no change.
- **G-code changes from batch 2A** (#390, #408).
  - First layer: support, support interface, raft base, walls and brim use Initial layer speed; gap infill and other infill use Initial layer infill speed (U1 and X1C: gap infill 50 to 105 mm/s). The first object layer over a raft takes first-layer speeds.
  - After a toolchange or custom G-code, Z goes back to layer Z plus Z offset. Short travels before an outer wall keep its acceleration.
  - Small holes (up to 0.2 mm) are ignored when avoiding crossings; the brim uses Initial layer speed; spiral vase drops very short segments.
  - A layer height outside the printer's limits offers Adjust or Ignore, and Ignore sticks. The same check now covers Initial layer height. The default output name uses the project name. The tree-support Adaptive layer height option is gone.
- **Support interface layers change** (#395). N configured top interface layers now print N (it was N+1); build-plate-only classic trees print far fewer interface patches; Top Z distance 0 no longer means soluble on its own; bottom-only interfaces print; interface lines keep one angle per layer; organic and classic trees give the same G-code every slice. Support length and interface length move by a few percent in most support cases.
- **Stabilizers and spiral vase** (#406). Slicing is refused if both are on.
- **Your presets stay local** (#414). User presets are no longer synced to any cloud account, and the sync options are gone from Preferences and dialogs. Files in `user/default` are untouched.
- **No separate network plug-in download** (#415). The app no longer offers to download a separate network plug-in; if the plug-in is missing it shows a reinstall message.
- **Smaller logs** (#412). At log level Info, printer status pushes no longer fill the log (one sample file was 108 MB, 97 MB of it these lines). Debug and Trace bring the detail back.
- **Cancelled prints show as cancelled** (#422). A Bambu print you cancel is reported as cancelled, not failed. A real failure is reported 5 to 10 seconds after the printer says so.
- **One Mobile Hub per data folder** (#393). A second hub for the same folder exits instead of running alongside, and the Device tab retries page errors quietly. Hubs from older builds do not take part, so an old and a new hub can still overlap.
- **Two-nozzle send dialog** (#413). The tray picker shows only the filament's own extruder; before, the other side could be picked and Send was then blocked.

## Fixes

- **Command-line slicing crashed after writing the G-code** when thumbnails were rendered (#411), and could crash or hang when several objects warned at once (#396). The app itself was not affected by the second.
- The Stream tab no longer logs an error for a missing icon (#422), and the Device tab camera page no longer raises a script error on Mac (#418).

## Known limitations and not tested

- **Checked by hand by the owner and passed:** #390 and #408, #395, #406, #407, #419 (all import routes) and #422 (one cancel alert; a second "failed" alert in that test came from an older test copy running alongside). The Mac checks above, plus go2rtc with WebRTC on 8555, Tailscale remote access, the camera and an H2C send and print, passed on the same Mac.
- **Merged without a hand test:** #412 (logs), #414 (preset sync) and #415 (plug-in download).
- **Not tried on a printer:** the X2D, P2S, A2L and H2D Pro definitions and the X2D 3MF fixes (#409; the author had no X2D), and the external spool for printers other than the X2D (#413).
- **Support interface, accepted as upstream behaviour** (#395). Organic supports put no interface on a slope when the tree tip is thin (below about 1.13 mm; use 1.2 mm). Tree supports end the interface where a layer's overhang drops below 1 mm2, about 2 mm lower than normal supports on a tapering slope.
- **Mac and Linux:** only one Mac was used. The macOS CI step that bundles go2rtc has not run in CI yet, so the first release build is its test. The hardware H.264 ffmpeg template and the exact `socketfilterfw --listapps` and `--getallowsigned` output formats are unverified. Linux hub code was only compiled and unit-tested under WSL, and has no go2rtc bundle.
- The Windows camera component offer (BambuSource) is unchanged and still downloads from Bambu if you say yes.
- The A2L bed art is not ported yet.
- Still open from 2.4.5.0: the Snapmaker #962 port (#350), the inverse hole direction (OrcaSlicer #12669), and the remaining OrcaSlicer catch-up batches.

## Under the hood

- Tests merged with their PRs for every item above, including a headless gate for the Export Preset Bundle page and fixture tests for the hub's Tailscale, firewall and port parsers.
- New printer definitions N6, N7, N9 and O1E (`printers/version.txt` 01.10.00.03) and an updated X2D template (`BBL.json` 02.00.00.78).
- The core-profile GL test now shares one GL context (#394); it looked hung on a busy machine. The product is not affected.
- The macOS build job fetches and checks go2rtc; Windows `.exe` and `.dll` tools are left out of Mac and Linux packages.
